## 1. Objective
Build an authorized, market-scoped, auditable Price List module that returns every eligible reference price (never just the cheapest), preselects deterministically (Customer → Market → General), records every selection append-only, and never retro-prices history. M10 Quotations integration is out of scope; this task ships the selection contract standalone with context_type = 'AD_HOC'.

## 3. Scope
In scope:
- Price List CRUD + items + approve/archive, market-scoped (?market=<code> mandatory)
- Eligible price lookup returning ALL eligible references with deterministic preselection
- Price selection recording (reference / manual / override) with reason policy and append-only history
- UI: Price List grid, create/edit drawer, detail page with items, Eligible Prices selection panel, selection history
- Grants, OpenAPI, migration 0005 + down, unit/integration/e2e tests

Out of scope:
- Any part of M10 Quotations (no quotation routes, PDF, FX conversion, quotation_lines writes)
- Currency conversion, price floors, approval amount thresholds
- Bulk CSV import/dry run
- New roles, new dependencies, new infrastructure
- Retroactive repricing of anything

## 4. Owner decisions confirmed during planning
D1 Lifecycle stored as DRAFT→APPROVED→ARCHIVED only; ACTIVE/SCHEDULED/EXPIRED derived at query time from status + valid_from/valid_to.
D2 New append-only table price_selections (migration 0005) + mandatory audit_events row in the same transaction.
D3 Grants mirror M07: admin+manager get create/read/update/approve/archive/select/override; sale gets read+select; accountant gets nothing. No maker-checker.
D4 AC-20 tie-break: narrowest matching quantity tier → latest valid_from → lowest id. Never "lowest price".
D5 price_list_items.specification_version_id IS NULL = wildcard (eligible for any revision); non-null = exact revision match only.
D6 Currency CHECK (USD, VND) matching Quotation input policy; eligible lookup filters by requested currency, never converts.
D7 Standalone selection API/UI uses context_type='AD_HOC', context_id NULL; M10 later adds context_type='QUOTATION_LINE'.
D8 price_basis CHECK (NET, GROSS, OTHER); OTHER requires non-empty price_basis_note.
D9 Quantity tier overlap allowed, not blocked; create/edit responses carry overlaps[] rendered as an inline non-blocking warning (AGENTS.md §6).

## 5. Design — Database (db/migrations/0005_price_lists.sql + .down.sql)
price_lists: ADD created_by (backfill 0 then NOT NULL), approved_at, archived_at, archive_reason; CHECK status IN (DRAFT,APPROVED,ARCHIVED); CHECK currency IN (USD,VND); CHECK approved fields present when APPROVED; CHECK archived fields present when ARCHIVED; new index price_lists_eligibility_idx (market_id, status, tier, valid_from, valid_to).
price_list_items: ADD price_basis_note; CHECK unit IN (KG,MT,CTN,PCS,LB); CHECK price_basis IN (NET,GROSS,OTHER) + OTHER-requires-note; index price_list_items_lookup_idx (market_id, product_id, unit, valid_from, valid_to); BEFORE UPDATE trigger freezing commercial columns once parent list leaves DRAFT (SQLSTATE 55000); matching BEFORE DELETE guard.
New table price_selections: append-only, integer identity PK, no FOREIGN KEY/REFERENCES; columns per plan §4.1 (listed_amount, selected_amount, currency, unit, price_basis, quantity, reason, source_metadata jsonb, selected_by, selected_at, request_id); CHECKs enforcing REFERENCE/MANUAL/OVERRIDE reason policy and REFERENCE=listed-amount equality; BEFORE UPDATE OR DELETE trigger rejecting mutation (same pattern as 0002_audit_events_append_only.sql); indexes on (market_id, context_type, context_id), (market_id, product_id, selected_at DESC), (market_id, price_list_item_id).
Also: new assertions in scripts/validate-migrations.ts and a dated entry in db/operation/sql_history.md.

## 13. Acceptance criteria
AC-01 Authorized create → row+audit in one transaction.
AC-02 Filter by SKU/unit/currency/quantity/date → only eligible returned.
AC-03 Multiple eligible prices → all displayed, not just cheapest.
AC-04/05/06 Customer→Market→General preselection in that priority order.
AC-07 Select another eligible reference → allowed without reason.
AC-08 Exact listed reference amount → no reason.
AC-09 Manual price entry → reason required.
AC-10 Override listed amount → reason required.
AC-11 Manual/override reason persisted and visible to approver.
AC-12 Every selection records reference, listed amount, selected amount, actor, timestamp.
AC-13 Expired/unapproved price → not eligible.
AC-14 Invalid currency/unit/quantity basis → rejected.
AC-15 Unauthorized price modification → denied (403).
AC-16 Price List updated after quotation issue → historical quotation terms unchanged (proven at price-list/selection layer; quotation-level proof deferred to M10).
AC-17 Concurrent approval/selection → consistent eligibility, exactly one APPROVED winner.
AC-18 Mandatory audit failure → business transaction rolled back.
AC-19 Price search/filter/pagination → no unauthorized/cross-market data exposure.
AC-20 Multiple same-priority eligible references → deterministic preselection (D4 tie-break).

## 15. Risks
- Reason policy bypass via direct API → mitigated by server-side eligibility recompute + DB CHECK as second gate.
- Trailing-zero amount misclassified as OVERRIDE → mitigated by decimal.ts normalization both sides + explicit test (100 vs 100.00 vs 100.000).
- Concurrent approve/select (AC-17) → row lock + expectedVersion conditional update + Promise.allSettled double-approve test.
- Validity-window off-by-one across timezones → inclusive/exclusive documented, UTC timestamptz, boundary tests at valid_from, valid_to-1ms, valid_to.
- Baseline price_eligibility index leads with customer_id, won't serve tier scan → new price_lists_eligibility_idx, EXPLAIN checked in integration test env.
- Doc/schema naming conflicts (specification_id vs specification_version_id, effective_from vs valid_from, market_country vs market_id+tier) → SQL baseline wins; docs corrected in Documentation Decision step, not silently.
- created_by backfilled with 0 on existing rows → dev DB has zero price_lists rows currently, so backfill touches nothing.
- M08 UI/API could be read as "quotations done" → final report will explicitly state M10 integration as NOT IMPLEMENTED.
